# Financial-Year Ledger Views Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a global selected financial year (default = current FY) that scopes the Purchases/Sales registers and the Dashboard, while Stock stays live and carries forward across years.

**Architecture:** Backend `listPurchases`/`listSales` gain an optional `fyLabel` filter and a new `listFinancialYears()` is added; a renderer `FYProvider` context (default = `financialYear(today()).label`) feeds a sidebar `FYSelect`; the registers and dashboard read the selected FY from context and pass it to the list calls. Stock is unchanged (live carry-forward). No schema change.

**Tech Stack:** Electron + electron-vite, React 18, TypeScript, Mantine v7, better-sqlite3, Vitest.

## Global Constraints

- **Spec:** `docs/superpowers/specs/2026-06-25-fy-ledger-design.md` is authoritative.
- **Selected FY** is a renderer-side view filter; default = current FY (`financialYear(today()).label`, a `YYYY-YY` string e.g. `2025-26`); **not persisted** across launches.
- **FY-scoped:** Purchases register, Sales register, Dashboard. **NOT scoped:** Stock (live, carry-forward) — only a clarifying caption is added.
- **`fyLabel` is optional** on `listPurchases`/`listSales`; **no arg = all rows** (existing callers/tests must keep passing).
- An entry is filed under its invoice date's FY (unchanged); the selector never changes how data is written.
- No change to tax, numbering, stock draw-down, the invoice template, or the schema.
- Renderer reaches data only via `window.api.*`. Build stays green each task (`npm test` + `npm run typecheck` + `npm run build`). Do NOT run `npm run dev` headless.

```ts
import type Database from 'better-sqlite3'

export function listFinancialYears(db: Database.Database): string[] {
  return (db.prepare(`
    SELECT DISTINCT fy_label FROM
      (SELECT fy_label FROM purchases UNION SELECT fy_label FROM sales)
    ORDER BY fy_label DESC
  `).all() as Array<{ fy_label: string }>).map(r => r.fy_label)
}
```

- [ ] **Step 1: Create the FY context** (`src/renderer/fy.tsx`)

```tsx
import { createContext, useContext, useEffect, useState, type ReactNode } from 'react'
import { financialYear } from '../main/core/financial-year'
import { today } from './lib/format'

interface FYState { fy: string; setFy: (s: string) => void; years: string[] }
const FYContext = createContext<FYState | null>(null)

export function FYProvider({ children }: { children: ReactNode }) {
  const current = financialYear(today()).label
  const [fy, setFy] = useState(current)
  const [years, setYears] = useState<string[]>([current])
  useEffect(() => {
    window.api.listFinancialYears().then(list => {
      const merged = Array.from(new Set([current, ...list])).sort().reverse()
      setYears(merged)
    }).catch(() => setYears([current]))
  }, [current])
  return <FYContext.Provider value={{ fy, setFy, years }}>{children}</FYContext.Provider>
}

export function useFY(): FYState {
  const ctx = useContext(FYContext)
  if (!ctx) throw new Error('useFY must be used within FYProvider')
  return ctx
}
```

## Notes for the implementer

- The selected FY is a **view filter only** — it never changes how purchases/sales are written (their FY comes from the invoice date). Do not touch create/update paths.
- `listFinancialYears` is union-of-data; the renderer context merges in the **current** FY so the active year is always selectable even before it has any transactions (this is what makes a fresh new FY usable on day one).
- Stock is intentionally NOT filtered — `stockLedger()` stays live so prior-year lots remain visible and sellable. Only a caption changes.
- In Dashboard, remove only the `const month = today().slice(0, 7)` line; **keep the `today` import** — the `{today()}` date caption still uses it.
- `financialYear` is imported into the renderer from `../main/core/financial-year` (a pure function) — the renderer already imports pure helpers from `main/core` (e.g. NewSale imports `placeOfSupplyState`).
